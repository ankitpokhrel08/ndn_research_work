\section{Introduction}
\label{sec:introduction}

Internet usage has shifted decisively from host-to-host sessions toward content retrieval: video streaming, social media, and cloud-delivered services now dominate traffic, yet the underlying TCP/IP architecture still addresses \emph{machines} rather than the \emph{content} those machines exchange. The mismatch shows up as redundant transfers, avoidable latency, and scalability limits under load that is fundamentally about \emph{what} is being asked for, not \emph{where} it lives. Named Data Networking (NDN) \cite{zhang2010ndn} is one of the principal proposed replacements: it names data directly, retrieves it by name rather than by host address, and lets every router along the path cache and re-serve the content it forwards. Each NDN router maintains three data structures that realize this design. The Content Store (CS) is an in-network cache that lets a router satisfy a repeated request for the same name without forwarding it further; the Pending Interest Table (PIT) records every Interest a router has forwarded but not yet answered, so that the eventual Data packet can be sent back along the reverse path without a separate routing decision; and the Forwarding Information Base (FIB) maps name prefixes to outgoing faces, playing a role broadly analogous to an IP routing table but over names instead of addresses. This combination, stateful per-Interest forwarding plus universal in-network caching, is what gives NDN its efficiency gains, and it is also what gives NDN an attack surface with no direct counterpart in TCP/IP: state that accumulates per request, and a cache whose contents an adversary can influence merely by asking for things.

Two attack classes follow directly from this architecture. An Interest Flooding Attack (IFA) exploits the PIT: the adversary sends a sustained stream of Interests for names that are unsatisfiable or that resolve only after an expensive round trip, so that PIT entries accumulate, timeouts pile up, and routers begin emitting negative acknowledgements (NACKs) as they run out of state to hold new requests. Because a well-tuned IFA can keep every individual traffic feature within a plausible range, its signature is qualitative rather than volumetric: it lives in the joint pattern of elevated NACKs, a collapsing Interest satisfaction ratio, and PIT dynamics under stress, not in any single counter crossing a fixed line. Cache Pollution (CP), by contrast, exploits the CS: the adversary requests unpopular or effectively random content at a steady rate, evicting entries a legitimate population would have reused and forcing subsequent genuine requests out to the producer. Because CP's requests are still answered, the satisfaction ratio it produces looks normal, so it is invisible to any detector built around request success or failure. What CP does leave behind is added request volume; its detectability is therefore a function of how far above the legitimate background rate the attacker sits, not of any qualitative deviation. A detector built around a single threshold, on a single feature, is structurally unable to catch both: pushing the threshold tight enough to catch IFA's subtle multi-feature drift produces false positives on ordinary traffic bursts, while a threshold loose enough to tolerate those bursts is well above where CP's volumetric footprint first becomes visible.

The literature on NDN anomaly detection has largely treated "detection" as a property that either holds or does not at whatever attack rate the authors happened to simulate, typically a high, easily separable one. Reported results at a single high rate say nothing about the more consequential question: down to what attacker rate does detection remain reliable before it degrades to chance? We refer to this boundary as the \emph{detection floor}, the minimum attacker rate at which a detector still distinguishes the attack from legitimate background traffic at an acceptable false-positive rate. An attacker who wants to remain stealthy will operate as close to this floor as possible, so it is the floor, not the peak, that bounds how quiet a successful attack can be, and no floor has previously been measured for either IFA or CP. This gap compounds two others. First, much prior detection work leans heavily on PIT-derived features, following the textbook expectation that IFA manifests as PIT exhaustion; whether that expectation survives contact with a real forwarding daemon's polling behaviour is rarely tested directly. Second, evaluations are typically confined to a single platform and a single topology, leaving open whether a reported detection rate reflects the attack's true behaviour or an artifact of one simulator's traffic generator or one network's shape.

This paper addresses all three gaps with a single design: one unsupervised Isolation Forest detector, trained exclusively on clean traffic and requiring no labelled attack data, evaluated identically across two independent platforms and the same three topologies (tree, dumbbell, and DFN mesh, Figure~\ref{fig:topologies}). On miniNDN, an emulation platform running the real NDN Forwarding Daemon, behavioral features derived from NFD counters expose the detector to genuine forwarding-daemon dynamics rather than a simulator's approximation of them. On ndnSIM, an ns-3-based simulator, an attacker-rate sweep spanning hundreds of runs locates each attack's detection floor directly, rather than reporting a single operating point. The same unsupervised pipeline, the same feature-engineering philosophy, and the same three topologies are used throughout, so that differences between IFA and CP, and between platforms, can be attributed to the attacks and the network rather than to inconsistent methodology.

The contributions of this paper are:

\begin{itemize}
    \item \textbf{Detection floor as a security metric.} We introduce the detection floor, the minimum attacker rate at which reliable detection is sustained at a realistic false-positive rate, as the metric that actually bounds attacker stealth, in place of single-rate detection accuracy.
    \item \textbf{Two floors, one mechanism.} We measure and mechanistically explain two detection floors an order of magnitude apart: Cache Pollution, a volumetric attack, remains detectable down to approximately 44\,Hz, while Interest Flooding, whose signature is qualitative rather than volumetric, remains detectable down to approximately 1.8\,Hz.
    \item \textbf{One detector, cross-platform and topology-invariant.} A single unsupervised Isolation Forest, trained only on clean traffic, is validated on both a real forwarding daemon (miniNDN/NFD) and a simulator (ndnSIM), across three structurally different topologies, without per-deployment retraining.
    \item \textbf{Correcting the PIT-feature assumption.} We show that PIT-based features, the textbook signature of IFA, are non-discriminating under realistic polling conditions, and that satisfaction ratio, cache-hit ratio, and NACK rate carry the discriminating signal instead.
\end{itemize}

The remainder of this paper is organised as follows. Section~2 reviews related work on NDN security and anomaly detection. Section~3 describes the detection method, feature sets, and experimental design shared across platforms. Section~4 reports the emulation study on miniNDN. Section~5 reports the simulation study on ndnSIM and the attacker-rate sweep that establishes each attack's detection floor. Section~6 explains why the two floors differ by mechanism. Section~7 discusses implications and limitations, and Section~8 concludes.
